# PR0 决策：INSUFFICIENT_TRACE

本轮有限 CPU 诊断已结束。保留现有工程实现和隔离诊断，**停止推进当前 PR 提交协议独立论文假设，不自动启动方法实验**。此前 TilePlace 的 `KEEP_ENGINEERING_OPTIMIZATION_ONLY` 结项不变。

这一决策不是“没有观察”：32个固定查询、16项边界/事件见证和1项不同sink共享trunk检查已经回答了部分语义问题；但没有支持“排除容量混杂后，常规实际协议仍有值得新方法解决的主要开销”这一论文前提。

| 已获得的具体证据 | 对决策的含义 |
|---|---|
| diffeq/clma各16查询，生产/宽参考候选一致、重复搜索一致；固定提交序列与实际batch状态一致；独立四副本与拒绝回滚无不一致 | 本轮未触发 CORRECTNESS_BLOCKED。不是全系统、混合owner或最终硬件证明 |
| N成功32/32；P成功14/32，另18次版本拒绝；N中10个候选在当前状态新增超用 | P与N合同不同，不能把P拒绝当成N算法错误或改用P后称同算法对照 |
| N与S有10/32路径不同，旧路径当前成本更高；F失效27/32并重放后匹配S | 当前N没有严格串行等价；更强校验确有成本，但并非N现有义务。有限F相等不是普遍证明 |
| 完整评分唯一读集最大18048/38950，全部低于65535；小图能独立复现窄记录、路径池和queue容量失败 | 隔离了边界机制，却没有量化旧 clma 的实际容量失败比例；不能选择 ENGINEERING_LIMIT_ONLY 并声称旧失败已归因 |
| F验证总计1.209 ms，含回退搜索总计138.194 ms；N搜索总计65.124 ms、提交总计0.0221 ms | 记录/回退在更强合同下可见，原N提交在这32查询中很小。单次固定顺序且不同合同，不能形成加速倍率；未测硬件同步／驻留开销 |
| 旧完整读集臂最后965任务未完成、原始窄字段/池参数与逐次失败trace不足 | 不能把旧7.1093或30轮/8轮差异作为同成功条件的新协议收益；主要归因仍unknown |

新方法准入逐项判定：

1. **真实瓶颈：未通过。** 当前数据定位到保守F的27次失效，但F是新增的更强新鲜度合同；常规N无此版本拒绝。初始wave不是末期拥塞的代表样本，历史主要失败原因未消除。
2. **不同于普通校验的具体能力：未通过。** 单调成本事件/所有权语义可能提供更精细的证书，但本轮只有反例与既有合同区分，没有新协议、完备正确性条件或净收益证据。普通版本验证与缩小读集不构成贡献。
3. **预声明合同：诊断通过，方法未建立。** 本轮已清楚区分S/F/P/N；没有用关闭容量校验来伪装严格串行方法的加速。
4. **相同最终QoR与强CPU基线：未通过。** S是同算法局部语义参考，非VPR基线；本轮未完整路由，也无新native WL/CPD。
5. **最终硬件验证：未通过。** tree-seed最终实现的功能回验仍有旧审计所述缺口，实体U280不可用；本轮未启动任何硬件任务。

因此不选择 RESEARCH_GAP_SUPPORTED。INSUFFICIENT_TRACE 精确限定于旧差距归因及新协议研究准入，不撤销已经观察到的路径新鲜度差异，也不宣称PersistRoute所有潜在方法均无价值。若作者未来另行提出研究任务，应先有明确的新能力和合同；本轮没有自动排队、补样、扩展预算或切换其他项目的授权动作。

资源与终态：累计受控子进程外层单调墙钟 **20.768244秒**，其中两次CPU编译18.910273秒，其他诊断1.857971秒；子进程最大RSS **237176 KiB（231.6 MiB）**，全部exit0、无超时。资源上限3600秒/8 GiB，未靠用满预算扩张样本。正确性与性能独立运行；元数据整理、源码阅读和文稿时间不当作路由性能。
