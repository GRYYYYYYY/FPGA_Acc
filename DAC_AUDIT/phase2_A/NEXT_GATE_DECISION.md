# 阶段二资源决策

**REVISE_ONE_HYPOTHESIS**

这不是投稿通过，也不是启动正式矩阵的许可。本轮实验已经结束，不自动扩展；不生成 MINIMAL_FORMAL_PROTOCOL_DRAFT.md，因为完整成本、强基线预算控制与方法新颖性尚未达到继续正式协议的门槛。

本轮增加了三个开发例的可信工程证据：同源、同输入、同控制器下，完整 refinement 中位数比为 1.456×、1.702×、1.657×；全部提交候选及最终原生结果精确一致。25 个进程全部完成，花费 7342.197 秒墙钟，含预热；原始 13 例和 4 个失败全部保留。不能把这解释成 prefix 没有净收益。

但已有 prefix 是普通精确求和优化，现有控制器已经有 touched-net/changed-endpoint 增量计算，VPR 本身也已有增量时序成本维护。本轮没有证明可独立区分的方法贡献、cold-deployment 加速或同预算优于强基线。因此现有收益**不足以支撑主论文贡献**，不能直接进入正式论文矩阵。

profile 支持只保留一个具体假设：在固定 native feedback/timing epoch 内，按真实读写依赖复用不同 move/swap/macro 候选之间重复的**候选评分贡献项**，在 commit/rollback/反馈替换时验证或失效。它与既有 prefix 的差别是跨候选复用已计算贡献；与既有 net-cache 的差别是后者主要缓存当前 placement 的 before-cost。它尚未实现，也尚未证明区别于普通 memoization 或 VPR 的增量更新，不能把名字当作新颖性。

源码落点也具体：`_cost_pair` 在每个 changed connection 的 delta 中重新调用 `_connection_congestion(..., self.positions)`，而 `_net_cost` 只缓存整个当前 net 的合计值，没有直接提供可复用的逐连接贡献。跨候选复用这些项是可关闭、可验证的实现假设；可复用键比例与维护成本仍未测量，逐连接缓存本身仍不能充当新颖性证明。

量化依据：A 的代表性完整运行中 proposal 占 70.47%、56.66%、67.50%；每次分别有 21,062,020、64,461,504、53,947,702 次 pressure 查询。原 net-cache 命中率均超过 99%，索引/快照构建只有约 0.2–6.3 ms。继续优化索引构建或同类 net-cache 缺乏收益依据。拒绝候选仍消耗 18.370、89.114、54.831 秒闭环驱动时间，不能省略原生验证来制造收益。整个 proposal 即使无限加速，代表样本上界也仅 3.386×、2.307×、3.077×；这些上界不等于新机制可达收益。

基线可执行性已经闭合到一个真实入口：从共同 placement 进行 fresh-SA，再 route/analysis/check，总计 2.018 秒。该解合法但 CPD 6.61216 ns 劣于共同起点 6.59759 ns，未通过共同接受规则。结果既不否定所有 TP 优化，也不构成 TP 等预算胜出的证据。后续必须允许原生基线保留 B0，并按实际墙钟考察已完成必要验收的输出。

## 唯一后续否证方案（仅建议，本轮不执行）

先做方法区别检查：针对 VPR 已有增量连接 cost 和一般缓存，说明何种跨候选/事务历史的复用原来不存在，给出保守依赖集合与正确性论证。若无法区分，停止 A 当前论文路线，不用追加实验掩盖新颖性缺口。

若这一点成立，再为这一个机制单独冻结小协议。只用已暴露的 diffeq、clma；两臂都开启既有 prefix、generic parser 和同一控制器，只切新复用。沿用 seed/预算/接受规则，不增加 PE、融合控制器或 HLS。每臂一次 warmup、每例最多一对正式测量，提前固定 AB/BA；900 s/run，总墙钟不超过 2 小时。该建议不是已提交的第二份运行协议，启动前仍需单独冻结源码和完整候选签名。

先覆盖远处压力改变但端点未变、非移动成员改变 HPWL 极值、swap 两侧、macro 全成员、commit/rollback 与反馈替换的反例。所有枚举候选的整数成本、排序、提交 placement、决策、反馈、最终合法性/QoR 必须精确相同，比较数量不能为零。原生反馈改变时先保守全部失效；不能由端点未动推导 route/STA 未变。

前瞻资源门槛建议：在两例上均达到至少 15% 完整 refinement 净收益，包含索引、查表、依赖校验、失效、全部拒绝和原生闭环；否则否定该假设，不自动调阈值再试。15% 是下一轮可预注册的资源门槛，不是本轮既得结果。即使通过，也只是继续评估的必要条件；仍需冻结输入准备器身份、测量新 cold 外层成本、实现强基线的预算控制与相同最终 QoR 的比较、再选择未见设计。

本轮不宣称全 P&R/部署加速、相同总预算胜出、未见设计泛化、板卡速度、能耗或 3D 泛化。A 之外不启动新方向；E 只保留已有搜索阶段观察与成本缺口，B/C/D 保持原状态，DieRoute 不运行。
