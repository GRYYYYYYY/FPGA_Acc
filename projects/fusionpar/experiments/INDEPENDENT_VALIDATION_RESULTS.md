# FusionPAR 冻结控制策略的独立输入验证

本轮六个输入全部按预登记规则尝试，没有替换失败设计或按结果调整参数。
apex2、des、seq、spla 完成两组各五次重复，共 80 次 host 运行；八份独立发布
审计全部通过。s38584.1 和 tseng 的两组均在转换阶段因根时钟 `pclk` 被明确拒绝，
未进入 host 候选实验。因此输入支持覆盖为 **4/6**，不是六设计全部通过。

完整记录见
[`independent_validation_status_2026-10-13.json`](independent_validation_status_2026-10-13.json)，
其绑定原始 `study.json`、每组执行与独立审计、全部逐次样本和源码归档。协议
[`independent_validation_protocol_2026-10-13.json`](independent_validation_protocol_2026-10-13.json)
保持预登记时的字节与状态字段，实际完成状态以本结果和原始 study 为准。

## 输入、策略与证据范围

选择全集来自既有输入目录中除 ex5p/alu4/misex3 外、具有原生 baseline、完整
placement contract 和 PR 图数组的全部六个设计。缺少契约的 ex1010、s298、
s38417 在运行前即未入选，不属于按结果剔除。该集合独立于 FP 的开发结果，
但具有既有 TilePlace 来源，不能称为对所有上游工作都未使用过的数据。

所有模式使用原始合法 routed baseline、XML 导出后端、零树前缀时序权重、
相同 PR 内核和分支保留规则；成功提交后刷新原生完整 criticality。接受规则
固定为 native `(WL, CPD)` 严格字典序改善，两项均不超过最初合法状态的 102%。
没有 RC predictor、从 packing 开始的完整 P&R 或物理 FPGA 执行。

测量进程顺序运行；全部测量结束后才执行独立审计。已完成模式的五次完整
状态、事件和 timing 轨迹一致。审计重建 placement/site/route/resource 版本、
占用和原子发布，核对原生证书、QoR 门槛、失败不改状态、分支保留、修复和预算。
本轮合计 440 次候选评估：35 次 QoR 提交、405 次拒绝、115 次 timing barrier、
105 次布局修复。没有把 protocol probe 或 route-only 提交算作质量改善。

## 共享状态的分阶段与交错执行

每组请求三个 primary。分阶段模式选择合法不重叠移动后合成一个批量候选，
交错模式逐个评估并在提交后重选。实际为每次一个 batch 评估与三个交错评估，
不能把它们称为等 native 评估次数。两者共用已加载状态和同一分支保留路由器。

四个设计两种模式均没有接受改善，最终保持原始 baseline。下表时间为五次
subprocess 中位数，包含所有拒绝、原生验证和时序工作；含准备列为每个样本
加上该组一次完整转换费用。

| 设计 | 最终 WL / CPD(ns)，两模式相同 | 分阶段 host(s) | 交错 host(s) | 分阶段含准备(s) | 交错含准备(s) |
|---|---|---:|---:|---:|---:|
| apex2 | 16101 / 6.69869 | 8.723 | 18.407 | 12.287 | 21.972 |
| des | 12974 / 5.01530 | 23.056 | 77.119 | 27.566 | 81.629 |
| seq | 14194 / 5.45825 | 8.385 | 17.863 | 15.122 | 24.599 |

本预算下，额外交错评估没有带来最终质量改善，分阶段耗时更少。这里比较的是

增加预算后的交错策略必然无效。

## 成本分解与输入失败

host 的 native-adapter 计时包含候选状态序列化、Python 启动和整个原生适配
子进程，不是 VPR-only 时间。router 计时是独立、非重叠的 C-model 调用区间。
从完整 host subprocess 时间减去这两项所得的剩余费用，仍包含加载、候选生成、
快照、占用重算、其他验证、文件处理与簿记，不能全部归因于某一个算法步骤。
`prepare_ns`/`validation_ns` 等嵌套计时不再叠加。

| 设计/九预算模式 | native adapter(s) | router(s) | 其余 host(s) |
|---|---:|---:|---:|
| apex2 盲选 | 38.945 | 0.818 | 6.717 |
| apex2 反馈 | 39.532 | 0.821 | 4.725 |
| des 盲选 | 46.782 | 8.157 | 146.108 |
| des 反馈 | 45.452 | 8.027 | 157.661 |
| seq 盲选 | 35.045 | 1.669 | 8.584 |
| seq 反馈 | 34.918 | 1.764 | 6.138 |
| spla 盲选 | 81.132 | 4.165 | 45.837 |
| spla 反馈 | 78.276 | 4.974 | 31.873 |

各列分别取中位数，不能要求相加恰等于 host 中位数。des 的其余 host 费用尤其
明显；源码显示候选生成器会完整枚举并重复计算，但本轮没有把该剩余项进一步
测成纯候选生成时间，不能据此直接报告它的加速潜力。

每个设计/track 的转换只执行一次，完整费用计入该组每个样本；这些不是五次
独立转换测量。配置、构建和测试费用另存完整 receipt 与汇总。两个失败输入
仍发生了构建、测试和转换费用，它们的 outer process 时间与错误日志完整保留，
不能按零运行成本或零质量改善的成功样本处理。

s38584.1、tseng 的失败均为根时钟 `pclk` 的显式拒绝，证据分别见
[`s38584.1 失败记录`](independent_validation_s38584_clock_failure_2026-10-13.json)、
[`tseng 失败记录`](independent_validation_tseng_clock_failure_2026-10-13.json)。
后续 ignored-net 完整性与回写需求见
[`GLOBAL_NET_SUPPORT_NOTES.md`](GLOBAL_NET_SUPPORT_NOTES.md)。本轮没有删除时钟、
绕过拒绝条件、修复后覆盖失败样本或替换设计。

## 对框架与研究主张的影响

现有证据支持：在声明的输入范围内，C++ 联合事务、真实 PR C-model、原生验证、
时序屏障、分支保留、有界反馈和完整成本记录能够组成可重复的先行框架。
它不证明当前交错/反馈策略优于共享状态的分阶段执行，也不证明比成熟 TP 更优。
此前三设计九预算 TP 强参考同样只有混合结果。

现有反馈模式应继续作为显式实验模式，不因开发集 alu4 的改善而提升为推荐策略。
后续高级 TP/RC、ignored-net 支持、候选生成效率、二进制/HBM ABI 与硬件执行属于
后续实现或研究；策略改变后需要新的验证，不能继续沿用本集合的独立性标签。
