# FusionPAR 路由树前缀时序计价与验证开销

本阶段针对固定布局全网 PR 的 CPD 退化做受控诊断，不修改上游 PR 搜索内核，
不调整 QoR 门槛。`route_tree_timing_weight_q=0` 保留原行为；`256` 按 Q8 完整
计入已有树根到 seed 的近似边延迟，再乘连接 criticality。新扩展边的计价、
连接顺序、拥塞参数和事务边界 STA 更新策略均不变。没有增加 PR 内迭代 STA。

这是近似路径延迟，不是完整 VPR RC 树负载模型。两个权重都保留全部结果，
不能按设计挑选权重或只报告较好的 CPD。

协议见 [`tree_timing_cost_protocol_2026-10-13.json`](tree_timing_cost_protocol_2026-10-13.json)：

- 冻结 TP 原生输出上，固定布局全网 PR 对两个权重各重复五次，共 30 次。
  TP 阶段复用已执行并校验 SHA 的输出，本轮没有重新执行 TP。
- 原始合法 routed baseline 上，shared batch 与 interleaved 分支保留控制器
  各用两个权重、三个 primary 预算、两次重复，共 24 次。这是机制复验，
  不是新的五次性能验证。batch 一次原子评估与 interleaved 三次评估费用不同。
- 所有权重零结果须复现原归档的完整状态、事件与 timing 轨迹。

C++ 回归现为 113 项检查。新增构造用例让第一个 sink 建立慢前缀，第二个 sink
可选择该前缀或更快的独立路径，验证两个权重改变搜索 attachment；PR 与空树
控制的路径和搜索语义一致，保留树模式不改变已固定分支，也不重新搜索该分支。

## 验证开销记录

每次 native adapter 输出 `costs.json`，使用连续、互不重叠的 wall-clock 区间：
manifest、前置输入绑定、候选读取、placement 导出/约束检查、路由解析/占用重算、
RR XML 解析、route 导出、native check、timing export、后置绑定、证书写出。
独立审计检查阶段顺序、非负时间、求和等于总时间，且总时间不超过 host 中包围
全部 adapter 的时间。失败会保留未完成阶段的 tail，不能混作成功阶段比较。

这些区间不包括 Python 启动/import、host 写 candidate.state、开销记录自身写出
以及 CLI stdout。`native_check` 和 `timing_export` 各包含其上游 wrapper 的准备、
VPR 子进程和后处理；尚不能把其中的全部费用都归为 STA 算法本身。
外部独立审计在所有测量完成后执行；它与事务内所需的合法性/QoR 决策检查分开。
所有事务内检查保留在 host 和 charged 时间里。

## 完成结果

54 次运行及 12 套独立审计全部通过：16 次受 QoR 保护的 move 提交、32 次拒绝、
30 次原生合法的固定布局路由发布和 100 次 timing barrier。全部模式的重复状态、
事件和 timing 轨迹一致；所有权重零运行也复现此前对应归档的完整语义。
132 份 validation 成本记录完整，通过阶段和包围时间核对。

固定布局每组五次的最终质量一致：

| 设计 | TP 原生 WL / CPD(ns) | PR 权重 0 WL / CPD(ns) | PR 权重 256 WL / CPD(ns) | 两权重共同门槛通过数 |
|---|---|---|---|---:|
| ex5p | 9868 / 5.61423 | 9818 / 6.63478 | 10781 / 5.63868 | 0/10 |
| alu4 | 9561 / 5.96812 | 9630 / 6.80247 | 10250 / 5.91881 | 0/10 |
| misex3 | 10269 / 5.03800 | 10305 / 5.95697 | 11188 / 5.15081 | 0/10 |

共同门槛以最初原始 routed baseline 为参照：WL 和 CPD 都不得超过 102%。
权重 256 的 CPD 都通过这个门槛，但 WL 都失败；它改善了 CPD，不能作为
共同质量条件下的可用全网 PR 参考。三个 TP 原生输出本身均在共同 2% 门槛内，
是已经存在的合法参考；不能强迫它们承担失败的全网重路由费用再比较 FP。
TP 与 FP 的搜索预算和目标仍不一致，本阶段不报告两者的 speedup。

控制器每组两次的最终质量一致，表中提交数是每次的数量：

| 设计 | 模式 | 权重 0 WL / CPD(ns) | 权重 256 WL / CPD(ns) | 每次提交数 0→256 |
|---|---|---|---|---:|
| ex5p | shared batch | 9849 / 5.83751 | 9857 / 5.88580 | 1→0 |
| ex5p | interleaved | 9849 / 5.83751 | 9857 / 5.88580 | 1→0 |
| alu4 | shared batch | 9580 / 5.96812 | 9558 / 5.96812 | 0→1 |
| alu4 | interleaved | 9548 / 5.96812 | 9544 / 5.96812 | 2→3 |
| misex3 | shared batch | 10323 / 5.08031 | 10323 / 5.08031 | 0→0 |
| misex3 | interleaved | 10323 / 5.08031 | 10323 / 5.08031 | 0→0 |

权重 256 只在 alu4 改善最终结果，在 ex5p 失去原有改善，misex3 没有改善。
因此默认值保持 0，不按设计选择权重。本轮没有测试新权重下的反馈修复模式，
不能把两模式机制复验扩大为所有控制策略或独立测试集合的结论。

## 开销归因

所有 54 次运行合计 host wall time 为 555.716 s；其中 host 包围 native adapter
的时间为 398.450 s，成功记录的 Python validation body 为 385.903 s。
下面百分比以这些 validation body 为分母，并非完整 P&R 或 FPGA 时间占比：

| 阶段 | 累计时间(s) | 占记录的 validation body |
|---|---:|---:|
| RR XML 解析 | 135.202 | 35.04% |
| 原生 checker wrapper | 99.618 | 25.81% |
| 时序 exporter wrapper | 95.657 | 24.79% |
| 前后输入/源码绑定核验合计 | 15.780 | 4.09% |
| 其余解析、导出、证书和尾部 | 39.646 | 10.27% |

独立审计已验证这些区间不重叠且未超过 host 的包围时间。RR 图重复解析是可
直接定位的工程开销；下一步可以研究预先导出、校验后复用的不可变 node/switch
元数据，同时保持最终 `.place/.route` 字节、原生检查和状态语义一致。
这类转换缓存属于公共基础设施，不作为 FusionPAR 的独立算法贡献。

两种原生 wrapper 合计占约一半 validation body，但它们目前承担合法性、QoR
和 criticality 决策；不能只因成本高就从时间中扣除或静默跳过。
源码、原始样本、配置、审计与阶段汇总见
[`tree_timing_cost_status_2026-10-13.json`](tree_timing_cost_status_2026-10-13.json)。
